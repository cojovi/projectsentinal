# 90-day original-asset program — proposals, not completed reporting

Days are relative to a future approved start. No recurring job, external outreach, purchase or testing has been started.

| Window | Pillar / asset | Method and publishable evidence | Limits / gate |
|---|---|---|---|
| Days 1–15 | AI & Models: agent task ledger | Fixed small repository tasks; save prompts, versions, run logs, permissions, artifact diffs, failures and manual rescue. Repeat runs; report cost with date and task success rubric. | Planned, no product ranking yet; don't equate self-reported completion with working code. |
| Days 16–30 | Privacy & Power: permission change log | Fresh test account, synthetic non-sensitive data, dated settings screenshots, export fields, revoke/access/delete steps. Record region/version/account state. | UI behavior cannot prove server-side retention; no third-party personal data. |
| Days 31–45 | Big Tech & Platforms: policy version diff | Capture authorized public versions and archive URLs, exact changed passages, effect dates and affected user group. Publish diff with attribution and open questions. | Policy text establishes stated policy, not actual enforcement. Shared-source repeats are not confirmations. |
| Days 46–60 | Devices & Experiments: reproducible device brief | Inventory owned device, firmware, setup, power/latency measurements with instrument/units and raw files; repeatable checklist. | Do not buy hardware or claim a test before approval and actual data; sample size one stays explicit. |
| Days 61–75 | Signal vs Noise: claim genealogy | Trace one viral mechanism claim to its earliest available account; map dependent repetitions and missing links. Include dates, access notes, contradictory evidence. | Do not label a person deceptive from absence of evidence; unresolved stays unresolved. |
| Days 76–90 | Cross-pillar methods release | Publish sanitized artifacts, failures, reproducibility notes, revision log and a reader task to replicate. Cross-link relevant explainers and RSS. | Remove secrets/personal data, don't imply anonymous secure tip collection. Parent reviews release. |

Each asset needs a sidecar with actual cutoff, URLs, unknowns and claim dispositions. Copying a sister-site body is not an original asset. Publish findings only once evidence exists; revise the proposal if a method fails.
