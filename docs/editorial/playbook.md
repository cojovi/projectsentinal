# Protocol Sentinel publishing playbook

The publication desk is an Organization. Cody Viveiros is the verified owner, not an automatic author or reviewer of every post. Use the registry in `blog/authority/registry.json`. Historical names remain attribution records, with no invented biography or degree.

1. Generators save `_posts` drafts with both `draft: true` and Hexo-recognized `published: false`; `_drafts` storage is also excluded. Start with an explicit date, registered author, one of the five pillars and article_type (`analysis`, `explainer`, `opinion`, `news`, `asset-brief`). Preserve filenames after publication: they are canonical article/API keys. A frontmatter slug can remain an exact legacy alias. Do not rename it casually.
2. Open actual primary material. List exact supporting URLs, what each establishes, its publication/version date, and a reporting cutoff. Distinguish documents, company assertions, first-person observations, independent replication and opinion. Two links relaying one underlying account are one account.
3. Fill a sidecar from `review-template.json`. Claim example: `{"claim":"Specific attributed assertion", "disposition":"attributed", "sources":["https://actual-primary-document"], "unknowns":"Not independently replicated"}`. Source objects can include `url`, `label`, `underlying_account`. Never add a fake `reviewed: true`, invented source, reviewer, measurement or credential. Build validation is not factual verification.
4. Record unknowns visibly. Missing URLs get an explicit pending label, not invented links from source names. A documented status needs cutoff, sources, claims and a body hash; it still does not certify truth. Record the hash printed by the quality CLI after the final body edit.
5. Run `cd blog && npm run quality -- source/_posts/<file>.md --review reviews/<file>.json --sister-body /path/to/exported-sister-article.md`. Compare shared-source structure as well as five-word shingle overlap. Northstar Ledger and Protocol Sentinel share ownership. Document comparison and provenance before publication. Do not fetch or copy another profile/repo automatically; use an authorized local export. Substantial overlap (50% contained shingles) fails the automated gate. Editorial comparison still matters below that threshold.
6. Credit artwork, including `image_credit` or `hero_credit`. Synthetic pixel art is illustration, not documentary evidence. Label an original-asset proposal as planned until methods, artifacts and outcomes exist. Do not imply hands-on use from desk research.
7. Before publication, pass the quality CLI, change both flags to `draft: false` and `published: true` (or move out of `_drafts` with those flags), then run the Node 22 clean build and full tests from the repository root. Both the authority build and direct Hexo hooks gate published sources; setting `published: true` does not waive the gate. Legacy `draft: true` still excludes an article even with `published: true`. For reader changes, the parent verifies native navigation on its authorized public preview using condition-driven matching-content assertions; do not launch a localhost browser in this session. The host publishes `blog/public`. Review output and factual sidecars before the parent commits, previews or deploys. Generators save drafts and do not publish or notify search engines.
8. For corrections, document the actual changed claim, date, description and source. Do not call a layout, canonical or transparency repair a verified factual correction. Updates use source frontmatter only, never build mtimes. Avoid updating date/updated merely to refresh a feed.
9. Offer a relevant next read and RSS. No newsletter promise without delivery infrastructure. Public GitHub issues are not confidential intake; no response window is promised.

## Source layout

`blog/scripts/authority.js` normalizes rendered posts before the Aurora API mapper. `authority/contract.cjs` owns URL aliases, author resolution, dates, evidence and article schema. `authority/build.cjs` produces full response documents, canonical discovery XML and exact host routing. `source/authority/reader.js` hands off only after a matching article is present and updates route metadata. The complete fallback belongs to its original route: it hides elsewhere, restores on Back if needed, and is removed only after matching native content appears. Visibility does not depend on manifest availability. Vue stays mounted.

## Ordinary discovery

`scripts/notify-google.py` is intentionally disabled for article Indexing API mutations and does not read credentials. The article use case is ineligible for URL_UPDATED. Once the parent has verified a deployment, use the existing verified Search Console property to submit `https://protocolsentinel.com/sitemap.xml` and read back that exact sitemap entry. Discovery does not force indexing. No scheduler or notification was installed or run.

## Host routing review

`netlify.toml`: base `blog`, publish `public`, pinned Node 22, skip host HTML processing. Generated `_redirects` lists every article alias individually, then exact canonical 200 rewrites to `/post/<filename>/index.html`. Canonical and slash article/page forms both serve 200 with the extensionless, slash-free canonical (except `/`). There is no slash-only 301: Netlify normalizes trailing slashes before redirect matching, so such a rule redirects the canonical request to itself. No `.html` wildcard and no SPA catch-all. Netlify preserves incoming query strings by default; paths in aliases do not include queries. An unrelated HTML asset remains a file. Unknown paths receive the static `404.html` with an actual 404 at the host.

Netlify routing reference: https://docs.netlify.com/manage/routing/redirects/redirect-options/#trailing-slash (301, forced exact rules, default query forwarding, static 404). Cloudflare must preserve these origin status/Location responses and must not apply an old cache-everything or universal HTML rewrite. Parent should test exact legacy paths, query strings and genuine missing paths on the preview before promotion; this implementation does not change Cloudflare configuration.


Aurora 2.5.3's compiled navbar/sidebar request `/api/authors/blog-author.json` literally. The source-controlled API generator emits this as an exact copy of the registered `protocol-sentinel` Organization desk record, including its published post list and `/authors/protocol-sentinel` profile link. Navbar branding uses `site.author: Protocol Sentinel`; responsibility remains the desk record. Owner profile configuration does not assign historical articles to the owner.

Parent preview packaging: invoking Netlify CLI from the original repository with `--dir` pointing elsewhere can still compile redirect configuration from the original configured publish directory. For an isolated artifact probe, the parent must run from that artifact directory with its own `netlify.toml` using base/publish `.` and processing skipped, then inspect the actual compiled redirect count/rules. The parent-reported controlled probe verified 99 pages, 97 query-preserving article aliases, four XML files and four missing paths after removing only the 77 slash-source rules; that is prior artifact evidence, not validation of this final source build. Parent must rebuild/redeploy the final source and repeat public HTTP/native-browser checks. No deployment command is authorized here.
